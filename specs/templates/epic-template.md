## Epic Quality Checklist

<!-- Review this checklist before finalizing the Epic. Ensure it meets all quality standards before grooming/refinement sessions. -->

### 1. ✓ Delivers End-to-End User Value

- [ ] This Epic delivers a complete capability that users can actually use, not just a partial feature
- [ ] Users can see the benefit without waiting for dependent Epics
- [ ] The Epic creates measurable user impact

**Questions to ask:**
- Can users accomplish a meaningful task with just this Epic?
- Does this Epic stand alone or is it just a building block with no immediate user benefit?

### 2. ✓ Has Clear Boundaries

- [ ] The Epic has a well-defined scope with clear "in scope" and "out of scope" items
- [ ] The Epic doesn't overlap with other Epics
- [ ] The Epic is focused on one primary feature area, not a collection of unrelated features

**Questions to ask:**
- Could I explain the boundaries to a new team member in 2 minutes?
- Are there any items that could be removed to sharpen the focus?

### 3. ✓ Linked to PRD Goals or Success Metrics

- [ ] This Epic directly supports at least one goal from the PRD
- [ ] This Epic contributes to at least one success metric from the PRD
- [ ] The business case for this Epic is clear

**Questions to ask:**
- Which PRD goal(s) does this support? (Should be documented)
- How will success be measured after this Epic launches?

### 4. ✓ Can Be Broken Into Smaller User Stories

- [ ] The Epic has been broken down into 4-8 user stories (not too many, not too few)
- [ ] Each user story is small enough to be completed in one sprint
- [ ] User stories are independent and can be prioritized flexibly
- [ ] The stories follow "As a [persona], I want [action] so that [benefit]" format

**Questions to ask:**
- Can each story be tested and deployed independently?
- If one story is delayed, can others still be completed?
- Are stories sized appropriately for your team's sprint capacity?

### 5. ✓ Additional Quality Checks

- [ ] Description is clear to both technical and non-technical stakeholders
- [ ] Success criteria are objective and measurable, not subjective
- [ ] Dependencies have been identified and communicated
- [ ] Primary persona is clearly identified and their pain point is articulated
- [ ] Sizing estimate is reasonable and documented with rationale
- [ ] Epic is not too large (if sizing is "Large", consider breaking into multiple Epics)

**Questions to ask:**
- Would product, engineering, and design all agree with this Epic's definition?
- Are we trying to do too much in one Epic?
- Could this be split into 2-3 smaller, more focused Epics?
